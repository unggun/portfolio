## Overview

Deputy is a bridge between a task manager and a coding agent. It watches the tickets assigned to me, decides which ones an agent can safely do, and takes those to a merged pull request. That means triage, a grounded plan, an implementation in an isolated worktree, an independent review pass, a PR, and CI fixes until it lands. It ships with ClickUp, Jira and Claude Code. Swapping in another task manager or agent means implementing one small interface.

I built it because of the problem I wrote about in [When Agents Write the Code, Review Becomes the Bottleneck](/blog/when-agents-write-the-code-review-becomes-the-bottleneck). Generating code had stopped being the hard part. The hard part was everything around the code: deciding what's safe to automate, keeping humans in the loop at the right points, and making sure what reaches review deserves a reviewer's attention.

## How it works

Every tick, which is a scheduled run every 15 minutes, moves each ticket **one step and then exits**. Nothing blocks while it waits on CI or a person. If the laptop closes, the VPN drops or a run crashes, at most one step is lost, never a whole ticket.

## Key Features

- **Triage that only reads the ticket**: Each ticket is classified as executable, ambiguous (questions get posted back on the ticket), or human-only. Triage runs in an empty, isolated directory with no tools, so it judges the ticket's words and nothing else.
- **Grounded plans with a sign-off gate**: For anything above an approval threshold, a read-only analyst reads the actual repository and posts a plan. Nothing gets implemented until a human approves it.
- **An independent reviewer before any PR exists**: A separate review pass judges the pushed branch and can send it back for changes, up to a set number of cycles. Only approved work becomes a pull request, so human reviewers see fewer, better PRs.
- **Repo brain**: Each repository gets a plain-markdown notes file of things a run learned, like which env var the tests need or which review finding keeps recurring. It's written only after an approved review, it has a size cap, and anyone can edit it by hand.
- **Multi-workspace, multi-repo**: ClickUp and Jira sources can be mixed, each with its own GitHub identity. When one Jira ticket spans a backend and a frontend, triage sends it to both repos, and the ticket only reaches `done` when every PR has merged.
- **Honest spend limits**: On a subscription, the dollar figure the CLI reports is notional, and the quota is the real limit. So Deputy gates on daily tokens as well as dollars, and checks both before every agent run.
- **Read-only dashboard**: A local web view of what's stuck, what's running, what it cost, and whether the work landed. It opens the database read-only, so it can observe the runner but never act on it.

## Technologies Used

- **Python**: The runner, state machine, providers and CLI (`run`, `status`, `doctor`, `graph`, `serve`).
- **SQLite**: Local state per machine. The ticket's AI State field is the only state shared between machines.
- **Claude Code (headless)**: The agent for triage, planning, implementation and review.
- **git worktrees + GitHub CLI**: One isolated worktree per task, and every PR operation.
- **ClickUp & Jira APIs**: Ticket intake, comments, dependencies and status.
- **React + Vite**: The dashboard frontend, served by the runner.
- **systemd / cron**: Scheduling, on a laptop or a VPS.

## Challenges and Learnings

The hardest bugs weren't in the agent. They were in the plumbing around it, where a small leak quietly turns into wrong behaviour.

**Isolation is more than tool permissions.** Triage was meant to judge a ticket from its text alone. But launching the agent from inside a repo loads that repo's `CLAUDE.md`, settings, skills and git state into the context before the prompt is even read. Taking its tools away stopped it acting on the repo, but it was still being handed the repo. When I asked triage what project it was in, it recited the runner's own `CLAUDE.md`. Moving triage to a fixed empty directory with everything switched off fixed it. It now answers that it has no project context, and as a side effect a triage call dropped from about 31k input tokens to about 370.

**Killing a run has to kill everything it started.** A timeout that kills only the agent process leaves its shell commands, MCP servers and subagents running, still holding the worktree and still spending quota. Agents now lead their own process group, and the whole group is reaped. Their output streams to a per-run log as it's produced, so even a killed run leaves a readable record.

**Nothing secret should end up on a ticket.** Escalation comments carry raw subprocess output, and a ticket comment is permanent and visible to the whole workspace. Everything on that path is scrubbed, both by credential shape and by the exact values of the tokens the runner injected.

**Never adopt work you didn't start.** If a runner finds a ticket marked in-flight with no local record of it, for example after a reassignment or from a second laptop, it doesn't guess. It marks the ticket blocked, explains the handover in a comment, and waits for a person.

## Outcome

Deputy runs unattended on a 15-minute schedule. It turns the routine part of my ticket queue into reviewed pull requests, and it routes everything else to the right human with a clear reason. Each step is resumable and each wait is visible on the ticket, so I can trust it to run while I'm not watching. Most of the work went into making it safe to leave alone.
